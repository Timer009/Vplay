## 1. 项目定位

Vplay Studio 以 OpenGame（Apache-2.0，源自 gemini-cli）为内核，目标是成为
「AI 原生游戏创作工具」：一句话生成可玩的网页游戏，并在手机上继续下达修改指令。

奖项目标：NVIDIA DGX Spark「最佳 AI 原生游戏创作工具」。

## 3. 已知限制

1. **图像 / 视频 / 音频模态未启用**：只有 DeepSeek Key，缺少对应供应商 Key，
   生成物走占位或降级路径。这是预期行为，不是缺陷。
2. **跨互联网协同未验证**：Vplay 自身的远程通道只在局域网/本机验证过。
   外出时通过第三方工具远程控制家中电脑属于外部链路，不等于 Vplay 能力。
3. 远程通道默认只监听 `127.0.0.1`，不开公网端口。
4. 桌面端 Agent 与远程 worker 是同一台机器上的进程；远程任务以「正式用户消息」
   方式交给 CLI 执行，串行、不并发。

## 4. 风险登记

| 风险                           | 影响 | 处置                                                      |
| ------------------------------ | ---- | --------------------------------------------------------- |
| 无 Token 时误暴露控制面        | 高   | 未配置 `REMOTE_TOKEN` 时服务直接禁用控制接口（503）       |
| 提示词注入冒充「可信远程指令」 | 高   | 鉴权只在 HTTP 层；任务文本一律按普通用户消息处理          |
| 服务重启导致任务重复执行       | 中   | 重启时把 running/verifying 标记为 interrupted，不自动重跑 |
| 生成耗时导致手机端误判卡死     | 中   | 任务状态机 + 轮询 + 失败原因回传                          |
| 生成质量依赖模型               | 中   | 模板脚手架 + post-verify 兜底                             |
