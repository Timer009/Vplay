# 可信实验隔离评估（B11 / D）

> 结论先行：**当前没有 OS 级隔离**。环境变量白名单、浏览器 route 白名单、项目锁与 HMAC
> 都不是沙箱；模型进程与宿主同属一个 Windows 用户，理论上可读写该用户可访问的任何文件。
> 本文件如实列出信任边界、已实现能力与未实现隔离，不宣称证据不可篡改。

## 1. 当前信任边界（Windows x64）

```text
用户账号：当前交互用户（同一账号运行 server、worker、CLI 子进程、浏览器）
监听：127.0.0.1:8787 / 8788（仅回环）
模型子进程：node dist/cli.js -p "<prompt>" --approval-mode auto-edit
```

| 资源                               | 模型子进程可访问性 | 说明                                                            |
| ---------------------------------- | ------------------ | --------------------------------------------------------------- |
| 项目工作区 `projects/<id>/src`     | 可读写（cwd）      | 任务唯一允许修改的位置，但这是**约定**，不是内核限制            |
| 其它项目工作区                     | 可读写             | 同用户、无 ACL 隔离                                             |
| `VPLAY_HOME`（注册表、快照、证据） | 可读写             | 与工作区同用户；模型可篡改快照/证据                             |
| `.rollback-journal` / 锁文件       | 可读写             | 未做 ACL                                                        |
| 模型 API Key                       | 可读（显式注入）   | 调用模型所必需                                                  |
| `EVIDENCE_HMAC_KEY`                | **不注入子进程**   | 仅在 server 进程环境；同用户进程若读取父进程内存/文件仍可能获得 |
| `REMOTE_TOKEN` / 设备 token        | 不注入             | 子进程 env 显式名单，无 `REMOTE_*`/`VPLAY_*`                    |
| `NODE_OPTIONS` / `NODE_PATH`       | 不注入             | 防 `--require` 注入                                             |
| 网络                               | 不受限             | 无命名空间/防火墙隔离；可访问 LAN/tailnet/Internet              |
| 浏览器                             | 应用层 route 守卫  | 仅 Vision 的 Playwright route；不是 OS 网络隔离                 |

## 2. 已实现的“约束”（不等于隔离）

1. **环境白名单**：`remote/lib/worker.cjs` 只传系统变量 + 显式模型 key；剥离 `EVIDENCE_*`/`REMOTE_*`/`VPLAY_*`/`NODE_OPTIONS`。
2. **工作目录与提示词约定**：任务 cwd 指向项目 `src`，prompt 说明只能改该目录。
3. **项目锁 + 快照/回退**：防并发写与可恢复，不阻止恶意进程越界。
4. **浏览器网络守卫**：Vision 截图时阻止跨源请求并剥离跨源凭据；不是内核级网络隔离。
5. **HMAC + 全量 manifest**：可检出证据包被改写，但无法阻止能读取密钥/目录的高权限进程伪造。
6. **审批模式**：`auto-edit` 只表示不会自动应用；**不是 OS 沙箱**。

## 3. 可落地的隔离方案评估

| 方案                                | 可行性           | 未实现原因                                                             | 若实施的最小步骤                                                                                                                                |
| ----------------------------------- | ---------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 独立低权限 Windows 本地账号运行模型 | 中               | 需管理员创建账号、迁移 `VPLAY_HOME` ACL、调整 CLI 配置与 node 安装权限 | 创建 `vplay-agent` 标准用户；`icacls` 仅授予项目 src；Runtime 以服务账号运行；模型通过 `runas`/计划任务以 agent 账号执行；证据目录对 agent 只读 |
| AppContainer / Job Object           | 低-中            | Node/CLI/浏览器兼容性与调试成本高；未验证                              | 用 Job Object 限制子进程树、内存与网络；AppContainer 需重做文件/注册表能力                                                                      |
| Windows Sandbox / Hyper-V VM        | 中               | 需要虚拟化与镜像管理，超出本轮收口                                     | 在 VM 内跑 Runtime + 模型；宿主只暴露 127.0.0.1 转发；证据回传只读                                                                              |
| WSL2 / 容器                         | 中               | 需额外运行时与网络模式设计                                             | 容器内跑 CLI，只挂载项目目录；禁用 host 网络；证据挂只读                                                                                        |
| 只读挂载证据目录                    | 高（若已分账号） | 同账号无法同时写/只读                                                  | 证据目录 ACL：server 写、agent 读；agent 进程以另一账号运行                                                                                     |

## 4. 当前可接受风险（明确记录）

- 恶意/被提示注入的模型可以在用户权限内读取其它项目、修改证据或发起任意网络请求。
- 因此：
  - 不宣称「证据不可篡改」；
  - 不把 HMAC/哈希链当作 OS 隔离；
  - 不把 `auto-edit` 或环境白名单称为沙箱；
  - 真实工程（Spacer）与正式凭据不应在未隔离环境执行不可信模型的自动修复。

## 5. 验收前必须满足（若宣称“隔离”）

1. 模型进程使用独立低权限账号或容器/VM；
2. 项目目录只授予该账号必要路径；其它项目与 `VPLAY_HOME` 不可读；
3. 证据目录对模型只读；HMAC 密钥不在模型可读范围；
4. 网络出口受控（默认拒绝，仅允许模型端点）；
5. 用负对照证明：模型进程无法读取 `EVIDENCE_HMAC_KEY`、无法写 `evidence/`、无法访问其它项目。

在满足上述 5 条前，本仓库一律标记 **OS_ISOLATION=NOT_IMPLEMENTED**。
